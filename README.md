# RUHUB Flow — размещение на GitHub Pages

Готовая сборка интерфейса RUHUB Flow 1.9. Совместное редактирование, библиотека Blackmagic, цвета кабелей и ручная форма линий сохранены.

GitHub Pages размещает интерфейс. Общие проекты и права доступа обслуживаются отдельным сервером: по умолчанию используется действующий сервер RUHUB Flow. Это не полный перенос серверной части на GitHub. Существующая база не копируется и не удаляется.

## Перед первой публикацией

1. Подключите GitHub к ChatGPT или выполните вход в GitHub CLI на своём компьютере. Не передавайте пароли и токены в чат.
2. Создайте репозиторий `ruhub-flow`. Для GitHub Free с Pages он должен быть Public: исходный код интерфейса станет общедоступным. Данные схем и ключи доступа в этот пакет не входят.
3. Сообщите адрес репозитория. На действующем сервере нужно добавить **точный origin** будущего Pages-сайта (например, `https://ваш-логин.github.io`) в `FLOW_ALLOWED_ORIGINS`. Включение выполняется отдельно от размещения кода. Нельзя указывать `*`.
4. Загрузите содержимое этого пакета в корень репозитория, включая `.github/workflows/pages.yml` и `package-lock.json`.
5. В репозитории откройте Settings → Pages → Source → GitHub Actions.
6. Запустите Actions → Publish RUHUB Flow → Run workflow. При последующих изменениях ветки `main` публикация запускается автоматически.

Workflow сначала проверяет, разрешает ли сервер запросы с адреса Pages. Пока origin не добавлен на сервер, публикация останавливается с объяснением. Это защищает от запуска интерфейса с неработающим сохранением общих схем.

## Настройки

В Settings → Secrets and variables → Actions → Variables можно задать:

- `FLOW_API_ORIGIN` — HTTPS-адрес серверной части без пути; текущий сервер указан по умолчанию.
- `FLOW_PAGES_ORIGIN` — точный origin своего домена, если используется собственный домен.
- `FLOW_PAGES_BASE_PATH` — `/` для собственного домена или `/имя-репозитория/`. Для стандартного адреса GitHub Pages путь определяется автоматически.

Переменные не должны содержать пароли, API-токены или ключи проектов: они попадают в публичную сборку. API-адрес является публичной настройкой, права на схему передаются отдельным ключом из её ссылки.

## Сборка локально

Установите Node.js 24 LTS, затем выполните:

```sh
npm ci
npm run check
npm run build
```

Статические файлы будут в `outputs/github-pages`. Для локальной проверки пути по умолчанию используется `/ruhub-flow/`.

## После публикации

Откройте URL, который вернул GitHub Pages, создайте тестовую общую схему и откройте ссылку для редактирования во втором браузере. Проверьте сохранение после обновления страницы. Только после этого используйте новый адрес для работы.

Старые ссылки продолжат открывать старый интерфейс. Ссылку проекта можно перенести на новый адрес, сохранив целиком часть после `#`. Локальные настройки библиотеки, темы и список «Мои проекты» хранятся в браузере отдельно для каждого домена; экспортируйте пользовательские данные до смены адреса. При размещении на GitHub Pages настройки заново применяются на новом домене.

Официальные инструкции: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site
