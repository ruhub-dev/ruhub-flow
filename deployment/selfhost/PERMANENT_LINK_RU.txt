RUHUB FLOW — ПОСТОЯННАЯ ССЫЛКА БЕЗ НОВЫХ АККАУНТОВ И ДОМЕНА

Вход для вас и инженеров:
https://ruhub-dev.github.io/ruhub-flow/

Этот адрес получает текущий адрес компьютера из вашего GitHub-репозитория.
После запуска START_INTERNET.cmd программа проверяет туннель и сама обновляет
connection/current.json. В браузере затем отображается адрес туннеля.
Сайт, пароли, схемы и история работают и хранятся на вашем компьютере.
GitHub хранит только исходники и публичный адрес подключения.

КАК ОБНОВИТЬ СУЩЕСТВУЮЩУЮ УСТАНОВКУ
1. Остановите старый запуск Ctrl+C.
2. Полностью распакуйте архив обновления в отдельную папку.
3. Запустите INSTALL_UPDATE.cmd и выберите свою рабочую папку RUHUB-Flow.
   В ней должны находиться runtime\node.exe и data\flow.sqlite.
   Установщик сохраняет прежние файлы программы в updates\before-stable-link-...
   База и резервные копии не заменяются, старую базу из первого архива не копируйте.
4. Автоматически откроется SETUP_GITHUB.cmd. Это однократная настройка:
   • В открывшемся GitHub войдите в существующий аккаунт ruhub-dev.
   • Repository access -> Only select repositories -> ruhub-flow.
   • Repository permissions -> Contents -> Read and write.
   • Выберите срок действия ключа, затем Generate token.
   • Скопируйте ключ и вставьте в окно настройки на своём ПК. Ввод скрыт.
   • В чат, GitHub-файлы или письма ключ не отправляйте.
5. После сообщения об успешной настройке запустите START_INTERNET.cmd.
6. Дождитесь сообщения «ПОСТОЯННАЯ ССЫЛКА»; браузер откроется автоматически.

ПРАВА И ХРАНЕНИЕ КЛЮЧА
Fine-grained token выдаётся только существующему репозиторию ruhub-flow
с разрешением Contents: Read and write. GitHub не ограничивает это разрешение
одним файлом; сама программа изменяет только connection/current.json.
Ключ не включён в архив. Он вводится на вашем компьютере, сохраняется
в data\github-token.dpapi в зашифрованном Windows виде, привязанном к вашему
пользователю Windows, и передаётся только в HTTPS-заголовке API GitHub.
При истечении/отзыве ключа повторите SETUP_GITHUB.cmd и перезапустите сервер.
На другом компьютере или под другим пользователем Windows настройку повторяют.
Для отключения автоматического обновления остановите сервер и удалите этот
локальный .dpapi-файл; при необходимости отзовите ключ в настройках GitHub.

ССЫЛКИ НА СХЕМЫ
Новые ссылки из кнопки «Поделиться» начинаются с постоянного GitHub-адреса.
Они сохраняют ключ выбранной схемы в части после # и продолжают работать
после перезапуска туннеля, пока владелец не отозвал доступ. Ключ схемы
не отправляется на GitHub при переходе по ссылке.
Ранее выданные ссылки с trycloudflare.com сами не меняются: выдайте новые.

ВХОД И НАСТРОЙКИ БРАУЗЕРА
После смены адреса туннеля в кабинете потребуется войти снова. Аккаунт,
пароль и серверные схемы сохраняются. Локальные настройки браузера
привязаны к адресу туннеля, поэтому могут потребовать повторной настройки.
Постоянная входная ссылка не делает адрес в строке браузера постоянным.

КОГДА КОМПЬЮТЕР ВЫКЛЮЧЕН
GitHub-страница остаётся доступной, но показывает, что сервер не отвечает.
При штатной остановке Ctrl+C программа также отмечает сервер выключенным.
После внезапного отключения питания это обнаруживается проверкой соединения.
Компьютер должен работать без сна и с интернетом для совместной работы.

ЕСЛИ ССЫЛКА НЕ ОБНОВИЛАСЬ
• Программа показывает прямой адрес туннеля — им можно воспользоваться.
• Ошибка GitHub 401/403: проверьте ключ, срок действия, репозиторий и Contents.
• При 409 программа сама повторяет обновление с актуальным состоянием файла.
• Если туннель ещё подключается, программа повторяет попытку каждые 15 секунд.
• На GitHub-странице есть «Повторить» и «Открыть напрямую».
• Сообщения туннеля находятся в logs\tunnel.log. Ключ там не печатается.

Для интернета продолжайте использовать START_INTERNET.cmd.
START_LOCAL.cmd и BACKUP.cmd работают как прежде.
