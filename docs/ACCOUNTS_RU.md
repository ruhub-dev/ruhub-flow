# Личные кабинеты RUHUB Flow

Регистрация по логину и паролю работает на существующем сервере. Google Cloud, Supabase и почтовый сервис не требуются.

## Как начать

1. Откройте https://ruhub-dev.github.io/ruhub-flow/ и вкладку «Регистрация».
2. Укажите имя, логин (3–32 латинских буквы, цифры, точка, дефис или подчёркивание) и пароль от 12 до 128 символов.
3. Скачайте или скопируйте резервный код. Он показывается один раз; отметьте, что сохранили его, и перейдите в кабинет.
4. Создавайте схемы с нуля или открывайте пример. Вкладки кабинета: все проекты, свои схемы, доступные вам.
5. Для совместной работы отправьте коллеге ссылку из «Поделиться». Коллега регистрируется или входит, открывает ссылку; схема добавляется в его кабинет с выданной ролью.

## Восстановление

«Забыли пароль?» → логин, резервный код, новый пароль. Прежний резервный код становится недействительным; выдаётся новый. Все старые сессии кабинета отзываются. Для проектов, созданных в кабинете, отзывается и доступ старой сессии к API редактора.

Без пароля и резервного кода автоматическое восстановление невозможно: почта не собирается и письма не отправляются. Секретные ссылки на схемы остаются отдельными разрешениями; владелец может отозвать ссылки редакторов и зрителей через «Поделиться».

## Существующие схемы

Кнопка «Перенести схемы» добавляет проекты, сохранённые на текущем origin браузера. Также можно открыть сохранённую ссылку — доступный проект попадёт в кабинет. При смене домена browser-local список не переезжает автоматически. Локальные JSON-файлы можно импортировать в редакторе и сохранить как новый проект кабинета.

## Технические сведения

Пароли: scrypt N=32768, r=8, p=3, dkLen=32, случайная соль 128 бит. Параметры фиксированы и не берутся из пользовательского ввода. Одновременно на один серверный isolate выполняется только одно хеширование, чтобы ограничить потребление памяти.

Сессии: случайный токен 256 бит, срок 7 дней; в БД хранится только SHA-256 токена. На клиенте токен хранится в localStorage текущего origin (GitHub Pages и сервер находятся на разных доменах). Публичные конфигурации и логи не содержат пароли, токены или резервные коды.

Восстановление: случайный код 256 бит хранится только как привязанный к пользователю хеш. Замена пароля и кода выполняется через сравнение версии записи; версии сессий проверяются на сервере. Старый код нельзя использовать повторно.

Ограничения попыток: атомарные счётчики в БД для IP и логина, отдельные окна входа, регистрации и восстановления. Клиент получает Retry-After. Неверные логин/пароль/код дают общее сообщение.

Доступ: серверный список проектов по user ID. Секретные ключи конкретных проектов выдаются только пользователю с соответствующим сохранённым разрешением. Новые личные проекты требуют и действующей сессии приложения, и ключа проекта. Старые схемы с capability-ссылками сохраняют прежнюю модель доступа.

Все миграции добавочные; исходные схемы и база не удаляются. Старые OAuth-таблицы сохранены для целостности истории миграций, но OAuth-маршруты и зависимость jose удалены. Переменные Google не нужны.

Проверки: `pnpm exec tsc --noEmit`, `node --test tests/account-access.test.mjs`, сборка сервера и `npm run check && npm run build` для пакета GitHub Pages.
