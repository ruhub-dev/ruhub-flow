# Google-вход и личные кабинеты RUHUB Flow

Код реализует вход через Google напрямую. Supabase не используется.

## Однократная настройка Google Cloud

1. Создать или выбрать проект в Google Cloud Console.
2. В Google Auth Platform заполнить Branding: имя приложения RUHUB Flow и собственный контактный email. Не запрашивать доступ к Gmail, Drive или другим Google API.
3. Audience: External. Для пробного запуска оставить Testing и добавить email инженеров в Test users. Для входа остальных пользователей перевести приложение в Production, выполнив требования, которые покажет Google.
4. Clients → Create client → Web application, имя RUHUB Flow.
5. Authorized redirect URIs, точное значение:

   `https://ruhub-signal-flow.hubwork-1806.chatgpt.site/api/auth/callback`

6. Если консоль запрашивает JavaScript origin:

   `https://ruhub-dev.github.io`

7. Скачать JSON OAuth-клиента. Client Secret нельзя размещать в GitHub, фронтенде, README или переписке с инженерами.

## Настройки сервера

Runtime variables в существующем сервере Sites:

- `FLOW_GOOGLE_CLIENT_ID` — client_id из OAuth JSON.
- `FLOW_GOOGLE_CLIENT_SECRET` — client_secret; сохранить как secret.
- `FLOW_GOOGLE_CALLBACK_URL` — точный callback выше.
- `FLOW_ALLOWED_ORIGINS` — сохранить `https://ruhub-dev.github.io` и любые другие существующие разрешённые origin.

После записи переменных повторно развернуть сохранённую версию сервера. До наличия всех трёх Google-параметров редактор продолжает работать со старыми общими ссылками. Кнопка «Личный кабинет» показывает, что вход ещё не подключён; фиктивная авторизация не включается.

## Что реализовано

- Google Authorization Code + PKCE; state привязан к HttpOnly Secure SameSite=Lax cookie.
- Проверка подписи ID token, issuer, audience, срока, nonce, azp и подтверждённого email.
- Идентификатор Google sub связывается с внутренним user ID; email не используется как ключ аккаунта.
- Возврат в приложение через одноразовый 60-секундный код, привязанный к verifier исходной вкладки. Токены Google не попадают в URL фронтенда.
- Сессия приложения на 7 дней; в БД хранится только SHA-256 хеш её токена. Выход отзывает эту сессию на сервере.
- Серверная выборка личных проектов по user ID, создание схемы и привязки к пользователю одной транзакцией.
- Полученный по приглашению проект добавляется в кабинет. Привязка сохраняет исходный ключ и роль; при отзыве ссылки соответствующий доступ пропадает и из кабинета.
- Существующие секретные ссылки продолжают давать доступ к конкретной схеме. Они не дают доступ к кабинету или списку чужих проектов.
- Перенос схем из списка, сохранённого на текущем origin браузера. После смены домена старые browser-local списки не переносятся автоматически: нужно открыть сохранённую ссылку или импортировать JSON схемы.

## Проверка после подключения

1. Реальный вход Google, возврат на GitHub Pages, отображение имени/email.
2. Создать проект, изменить схему, обновить страницу.
3. Другой Google-аккаунт не видит проект без приглашения.
4. Приглашение editor позволяет редактировать, viewer — только смотреть.
5. Отзыв ссылки удаляет соответствующий доступ из кабинета гостя.
6. Выход и повторное использование прежнего токена: `/api/account` возвращает 401.

Автоматические локальные проверки: `pnpm exec tsc --noEmit`, `node --test tests/account-access.test.mjs tests/google-identity.test.mjs`, серверная сборка и сборка пакета GitHub Pages. До настройки реального OAuth-клиента сквозной вход Google не считается проверенным.
